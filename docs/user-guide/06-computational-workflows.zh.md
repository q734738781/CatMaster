# 6. 计算与建模工作流

[上一章](05-agents-and-modules.zh.md) | [目录](README.zh.md) | [下一章](07-literature-writing-review.zh.md)

计算模块的共同流程是：明确科学问题，审查输入，准备 stage，做提交前 QC，查询当前远程任务 schema，人工确认，提交，收集结果，再做物理与数值验收。不要把“输入文件生成成功”或“调度器显示完成”当成研究结论。

## 6.1 通用任务合同

给 Experiment 的请求应明确：

| 项目 | 应说明的内容 |
|---|---|
| 科学目标 | 要比较、优化、筛选或测量什么 |
| 输入 | workspace 相对路径、结构版本、数据来源 |
| 物理设置 | 电荷、自旋、周期性、约束、温度、压力、场 |
| 方法设置 | 软件、泛函、基组、赝势、MLFF backend、精度 |
| 资源限制 | 是否允许远程提交、CPU/GPU、时限、预算 |
| 输出 | stage、结构、表格、图、日志和报告路径 |
| 停止点 | 哪些选择必须由用户确认 |

推荐先要求“只准备和审查，不提交”，检查完文件后再单独批准远程任务。

## 6.2 结构准备与审查

结构任务包括格式转换、标准化、超胞、元素替换、缺陷、吸附物、表面和路径图像。开始前至少核对：

- 元素、原子数、晶格、周期性和坐标单位。
- 分数坐标或笛卡尔坐标的含义。
- `Selective Dynamics`、固定层、约束和原子顺序。
- 周期边界下的最短距离和重叠原子。
- 分子电荷、自旋多重度和断键风险。
- 修改前后的原子映射。

如果用户要求保留 `Selective Dynamics`，它是贯穿转换、排序、切面和重新导出的硬约束。不要在中间格式转换时丢失后再凭猜测重建。

结构任务结束应至少产生：

```text
结构文件
变更摘要
关键几何或配位审计
约束保留检查
输入来源和生成脚本
```

## 6.3 Bulk、表面和吸附

### Bulk

常见任务包括 primitive/conventional cell、超胞、体相优化、缺陷和掺杂。比较多个结构时统一元素顺序、k 点密度、能量基准和约束。

### 表面与终止面

请求中写明 Miller 指数、层数或最小厚度、真空层、是否对称、固定层规则、允许的化学计量变化和极性处理。自动切面后检查：

- slab 法向和真空是否正确。
- 顶底面是否符合预期。
- 表面原子配位和 dangling atoms。
- 重复原子、异常短键和孤立碎片。
- 固定层与移动层。

“最高处原子”“配位数为 1”这类要求应转成可复核的几何或邻接筛选，并在报告中列出原子索引和阈值。配位数检查是经验筛查，不是唯一的化学稳定性判据。

### 吸附

明确吸附物构象、覆盖度、位点集合、朝向、初始距离和是否允许表面重构。多个候选应使用一致的命名和目录结构，并在提交前做碰撞、跨周期距离和化学合理性检查。

## 6.4 VASP 与 CP2K

Materials worker 可以准备 VASP 或 CP2K stage，并分析常见输出。

VASP 提交前检查：

- `INCAR`、`POSCAR`、`POTCAR`、`KPOINTS` 齐全。
- 元素顺序与 `POTCAR` 拼接顺序一致。
- `ENCUT`、k 点、电子和离子收敛设置有依据。
- 自旋、磁矩、偶极修正、DFT+U、色散和溶剂模型符合体系。
- 并行参数由远程 boot script 和资源共同决定，不在输入中随意写死。

CP2K 提交前检查：

- 主输入通常为 `job.inp`。
- `manifest.json` 和输入引用的 basis、potential、坐标或 restart 文件齐全。
- `RUN_TYPE`、周期性、CELL、POISSON、SCF、XC 和运动设置一致。
- AIMD 的 restart、速度和随机状态来源被记录。

计算结束后不能只看退出码。还要检查 SCF/几何收敛、警告、最终结构、能量轨迹、约束和预期输出是否完整。

## 6.5 路径、NEB 和过渡态

路径任务需要可靠的初态、终态和原子映射。提交前确认：

- 初终态元素和原子顺序一致。
- 固定原子和周期性一致。
- 插值图像没有原子碰撞或非物理跨胞跳跃。
- 图像编号连续，端点和中间图像数量符合 task 目录合同。
- climbing image、spring、收敛阈值和后续频率验证计划明确。

NEB 收敛只说明离散路径的优化状态。关键鞍点仍应做几何、力和必要的频率或 IRC 验证。

## 6.6 声子、弹性、能带、DOS 与热力学

这些后处理对前置计算和单位非常敏感：

- 声子：检查超胞、位移幅度、力收敛、虚频位置和声学支。
- 弹性：检查应变幅度、结构松弛策略、对称性和拟合区间。
- 能带/DOS：记录 k-path 来源、费米能级、展宽、自旋和投影定义。
- 热力学：区分电子能、ZPE、热焓、熵和自由能的基准、温度和标准态。

VASPKIT 或 ASE fallback 只负责计算路径。报告中要说明使用了哪一路、输入文件和关键假设。

## 6.7 Dynamics

Dynamics worker 覆盖 CP2K AIMD、LAMMPS 和 MLFF MD。请求至少给出：

- 初始或 restart 结构。
- 系综、温度、压力、时间步和总步数。
- thermostat/barostat 及时间常数。
- 速度来源、seed 和 restart 连续性要求。
- 输出间隔、轨迹格式和预期分析。

提交前检查单位、质量、周期边界、势文件、neighbor 设置和时间尺度。完成后先做健康检查：温度和能量漂移、体积、异常力、原子重叠、键断裂、逸出、轨迹帧数和 restart 可用性。只有健康检查通过后，再计算 MSD、扩散、RDF、配位和驻留时间等性质。

## 6.8 MLFF 推理

受管 MLFF backend 包括 MACE、FairChem UMA、MatterSim 和 ORB-v3。模板中只有 MACE 默认启用，其他 backend 必须由管理员安装、启用并绑定 resource。

任务类型：

```text
mlff_sp
mlff_relax
mlff_md
mlff_neb
```

不要在提示词中猜 backend 参数。让 agent 先查询 `get_avail_remote_task`，再用 `get_remote_task_spec` 获取当前 backend 和 operation 的完整 schema。部署的模型、默认 dtype、device 和支持操作可能变化。

MLFF 结果是模型预测，不等同于 DFT 真值。对于训练域外元素、异常配位、高能路径、带电体系、强磁性或反应断键，应检查不确定性或用独立方法验证。

## 6.9 ML 数据与 MACE 训练

ML worker 处理数据整理、主动学习、MACE train 和 eval。训练前记录：

- 数据来源、许可证、去重和 train/valid/test 划分。
- 能量、力、应力单位和参考能处理。
- 元素覆盖、构型分布、异常值和泄漏检查。
- 随机 seed、模型版本、超参数和硬件。

训练完成应保存 checkpoint、配置、日志、学习曲线和独立测试指标。只报告训练误差不足以证明模型可用于目标体系。

## 6.10 分子、xTB、CREST 与 ORCA

ORCA/xTB worker 处理非周期分子和簇。请求必须说明：

- 输入结构或 SMILES、质子化和互变异构状态。
- 总电荷与自旋多重度。
- 构象搜索范围和能量窗口。
- 溶剂模型、温度、方法和基组。
- 是否做频率、热化学、TS、IRC、TDDFT 或 NMR。

xTB/CREST 适合预优化和构象筛选，不自动替代后续高层级方法。ORCA 优化后检查终止状态和梯度；频率任务检查目标极小值无虚频、过渡态有且仅有预期虚频，并核对振动方向。

## 6.11 提交前和结果验收清单

提交前：

1. 输入目录符合注册 task 的 canonical layout。
2. 所有引用文件位于 stage 内。
3. 方法、单位、约束、电荷和自旋已写入审计记录。
4. 先查询 task spec，没有使用过期的静态参数名。
5. Review 模式下核对 task、work_dir、overrides、CPU/GPU 和清理策略。

完成后：

1. 读取 `status.json`、`stdout.log`、`stderr.log`。
2. 核对 receipt 的 `submission_hash`、任务数和状态计数。
3. 确认结果已合并回原始 stage，而不是只存在远程目录。
4. 检查程序级收敛和警告。
5. 对最终结构、轨迹或模型做领域 QC。
6. 把结论、限制和失败 case 写进独立报告。

远程布局、资源卡和失败恢复见[远程机器与任务执行](08-remote-execution.zh.md)。
