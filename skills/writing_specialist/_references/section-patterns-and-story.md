# Section Patterns and Story

Use this reference when a skill needs section-level structure rather than sentence-level editing.

## Story first

A strong paper usually has one central advance:

- what question was asked
- what answer is best supported
- why the answer matters

Everything else is support. If a figure, paragraph, or subsection does not strengthen that chain, demote or cut it.

## Recommended build order

For a research-backed manuscript, draft in this order:

1. Figures and tables
2. Results
3. Methods
4. Discussion
5. Introduction
6. Abstract
7. Title

This keeps the prose anchored to evidence rather than to aspiration.

## Introduction pattern: the cone

Move from broad to narrow:

1. field context
2. specific gap
3. why the gap matters
4. what this work does

Do not turn the introduction into a full literature review unless the paper type requires it.

## Results pattern

Results are not raw data dumps. Each subsection should usually follow:

1. setup or question
2. observation
3. comparison or contrast
4. local takeaway

Separate observation from interpretation when possible.

## Discussion pattern: the inverted cone

Move from narrow back to broad:

1. answer the research question
2. interpret the main findings
3. compare with prior work
4. explain limitations and uncertainty
5. state the broader implication without hype

Mechanistic explanation belongs here only when the evidence supports it.

## Methods pattern

Methods should tell the reader how the work can be reproduced:

1. workflow overview
2. materials, systems, or datasets
3. computational or experimental setup
4. analysis and post-processing
5. availability of scripts, source data, or artifacts

Write what was actually done, not a generic textbook method.

## Abstract pattern

A useful abstract usually contains:

1. context or problem
2. approach
3. main findings
4. implication

Keep it evidence-bearing. If a claim cannot survive in the abstract, it likely should not survive in the paper.

## Figure logic

Figures should carry the paper's argument:

- one figure, one job
- show the comparison that matters
- make uncertainty visible where relevant
- legends must define what is plotted, under what conditions, and what the reader should notice
